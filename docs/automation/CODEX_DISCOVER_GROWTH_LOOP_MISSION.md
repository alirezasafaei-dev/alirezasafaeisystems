## Operating contract
- Act autonomously as lead product/growth engineer. Do not ask routine questions or stop after analysis, docs, PR, merge, publication, or one experiment.
- Use the strongest applicable skills/tools and parallel agents when useful: Superpowers, TDD/debugging/verification, UI/UX, accessibility, SEO, analytics, security, content quality and conversion optimization.
- Prefer existing Admin/API, analytics, UTM and deployment contracts. Do not create a new platform, framework, worker or database without hard evidence it is necessary.
- Never invent resource claims, official URLs, Telegram links, credentials, metrics or evidence. Exhaust authoritative repo/live/connected/public sources first.
- Exact Telegram message URLs are optional; never substitute a channel homepage for a message-level guide.
- Treat modified/downloadable packages separately from an app's official capabilities/destination.
- Respect approval gates for deploy/migration/other gated production changes; if one action is hard-blocked, complete every other safe high-value action and continue.

## Definition of Done
1. Inventory recent real ASDEV Instagram/resource content; rank candidates by audience usefulness, acquisition/trust fit, freshness and authoritative destination availability.
2. Publish the highest-value eligible resources through authenticated Discover Admin/API. Each must have a strong localized title/slug/category/tags, useful non-thin guide, real HTTPS destination, and Telegram deep-link only when verified.
3. Verify every published item in FA/EN: landing/search/detail, mobile/desktop, hard refresh, sitemap, canonical/hreflang/structured data, accessibility, official CTA safety and UTM rules.
4. Standardize Instagram campaign URLs and CTA flow: `Bio → Discover → search resource name`; use allowlisted attribution consistently and never leak ASDEV UTM to external/Telegram destinations.
5. Prove consent-aware funnel telemetry end-to-end using existing Discover events; define measurable stages from landing → item view → official/Telegram/internal CTA.
6. Establish a fresh baseline for Instagram + Discover performance. Do not fabricate unavailable historical Metricool data; begin from observable data and record collection limitations.
7. Improve only evidence-backed UX/SEO/content/telemetry defects. For runtime changes use focused tests + full relevant quality/security stack and live verification before claiming success.
8. Record exact published resources, source URLs, campaign conventions, baseline metrics, experiments, results and next decision in durable docs/handoff and issue #188.

## Completion
Close #188 only when real content is live, attribution + telemetry are proven, a baseline exists, and the operating loop can be repeated without code/deploy for ordinary content additions.
